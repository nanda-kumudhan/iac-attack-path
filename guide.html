PROJECT GUIDE / v0.1

Project guide

The goal is an offline checker that compares base and head Terraform plans and flags new routes from the internet to data. This checkout provides delivery and presentation. The analysis engine is still to be hand-written.

A report is the boundary

Your engine emits a version 1 report with an analysis status, warnings and paths. Each path includes a canonical ID, change classification, certainty, an explanation and ordered resource steps. Source locations and remediation suggestions are optional.

The viewer displays those supplied steps. It does not parse Terraform, calculate reachability, find paths, perform a diff or compute a minimum cut. Raw Terraform plans cannot be opened yet. Browser analysis can be wired in once you write the browser-compatible engine.

Use the Action

First generate a report with your engine. The Action reads it via report-file, writes Markdown and SARIF, and fails for introduced paths, including possible paths. It rejects demo reports unless explicitly allowed for a presentation test.

The default is local report files and count-only logs. PR comments require an explicit opt-in and a token with write permission. Publishing comments, uploading SARIF or sharing reports sends resource details to GitHub. The workflow example is in docs/action.md in the repository.

The next hand-written stages

  1. Select three scenarios, pin their revisions and label the expected chains and negative controls yourself.
  2. Spike credential-free Terraform plan generation. Record what is actually achievable before relying on it in CI.
  3. Build the typed graph, parser and networking edges. Public ingress alone is insufficient: check routes, public addressing and service assumptions.
  4. Write BFS and path explanations, the limited IAM rules, canonical identity and before/after diff.
  5. Emit the report format, then connect the Action. Implement min-cut and explain the units of a change before describing a suggestion as smallest.
  6. Measure found, missed and false paths and runtime on 500 and 5,000 resources. Publish the failures alongside the successes.

Scope and honest limits

AWS only, a small IAM subset, heuristic chains and values that may remain unknown until apply. A reachable instance does not imply compromise or access to its credentials. Record those attack prerequisites in the engine's explanations. No claim of complete IAM evaluation or a guarantee of safety.

CloudGoat and TerraGoat are to be analysed statically only. This project includes no deployment workflow, no real lab plans and no evaluation scores. The synthetic demo is an interface example, not ground truth.

Local by construction

The production viewer bundles its scripts and Cytoscape locally, uses no CDN, analytics or backend, and blocks network connections with a content security policy. Selected reports stay in memory until cleared or the tab closes. The static site assets must still be served or downloaded once.
